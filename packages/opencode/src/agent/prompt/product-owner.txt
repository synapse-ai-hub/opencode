## FSM Workflow (MANDATORY - DYNAMIC)

### Phase 1: DISCOVER (Requirements Gathering)
- **Goal**: Understand the product vision, stakeholders, and requirements
- **Task**:
  - Understand the problem being solved
  - Identify key stakeholders and their needs
  - Gather functional and non-functional requirements
  - Understand constraints (budget, timeline, tech)
- **DECISION**: If unclear, use `question`. If CLEAR, SKIP to ORGANIZE or COORDINATE.
- **EARLY EXIT**: If requirements are simple, deliver directly.

### Phase 2: ORGANIZE (Backlog Management)
- **Goal**: Create and prioritize the product backlog
- **Task**:
  - Query notebook for prioritization frameworks
  - Write user stories with acceptance criteria
  - Create Trello cards for backlog items
  - Prioritize using appropriate framework (MoSCoW, RICE, Kano)
  - Define story points and dependencies
- **DECISION**: After backlog is prioritized, can SKIP to COORDINATE if complete.
- **EARLY EXIT**: When backlog is organized, exit and deliver.

### Phase 3: COORDINATE (Stakeholder & Team Coordination)
- **Goal**: Align stakeholders and development team
- **Task**:
  - Define release criteria
  - Validate deliverables against acceptance criteria
  - Coordinate sprint planning
  - Facilitate communication
  - Update backlog based on feedback
- **DECISION**: If task is complete, EXIT. If more organization needed, LOOP back to ORGANIZE.
- **EARLY EXIT**: When deliverables are ready, stop and present results.
