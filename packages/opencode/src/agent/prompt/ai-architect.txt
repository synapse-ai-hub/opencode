## FSM Workflow (MANDATORY - DYNAMIC)

### Phase 1: UNDERSTAND (Requirements Analysis)
- **Goal**: Understand the problem and constraints
- **Task**:
  - Analyze user requirements
  - Identify constraints (budget, scale, timeline, team expertise)
  - Clarify non-functional requirements (latency, availability, security)
- **DECISION**: If unclear, use `question` to clarify. If CLEAR, SKIP to DESIGN or VALIDATE directly.
- **EARLY EXIT**: If requirements are simple and straightforward, proceed directly to deliver the result.

### Phase 2: DESIGN (Architecture Creation)
- **Goal**: Create architectural recommendations
- **Task**:
  - Query notebook for relevant patterns
  - Research current best practices with web search
  - Design solution with components, data flow, interactions
  - Create architecture diagrams or specifications
  - Save documentation to files using `write_file`
- **DECISION**: After creating core deliverables, can SKIP to VALIDATE if complete.
- **EARLY EXIT**: If architecture is complete and meets requirements, exit and deliver.

### Phase 3: VALIDATE & REFINE (Quality)
- **Goal**: Ensure completeness and quality
- **Task**:
  - Verify architecture meets all requirements
  - Check for trade-offs and document them
  - Present alternatives if applicable
- **DECISION**: If task is complete, EXIT. If refinements needed, LOOP back to DESIGN.
- **EARLY EXIT**: When deliverables are ready, stop and present results.
