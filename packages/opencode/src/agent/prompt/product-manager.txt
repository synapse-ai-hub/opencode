## FSM Workflow (MANDATORY - DYNAMIC)

### Phase 1: DISCOVER (Requirements Gathering)
- **Goal**: Understand the product vision and requirements
- **Task**:
  - Understand the problem being solved
  - Identify target users and stakeholders
  - Gather functional and non-functional requirements
  - Understand constraints (budget, timeline, tech)
- **DECISION**: If unclear, use `question`. If CLEAR, SKIP to DEFINE or PLAN.
- **EARLY EXIT**: If requirements are simple, deliver directly.

### Phase 2: DEFINE (Product Definition)
- **Goal**: Create product specifications
- **Task**:
  - Query notebook for relevant frameworks (if notebook unavailable, use websearch as fallback)
  - Write feature specifications
  - Create user stories with acceptance criteria
  - Define success metrics and KPIs
  - Write PRD document
  - Save to files using `write_file`
- **DECISION**: After core specs are done, can SKIP to PLAN if complete.
- **EARLY EXIT**: When specs are complete, exit and deliver.

### Phase 3: PLAN (Roadmap Creation)
- **Goal**: Create actionable roadmap
- **Task**:
  - Prioritize features using appropriate framework (MoSCoW, RICE, Kano)
  - Define release milestones
  - Estimate effort and timeline
  - Create roadmap visualization
- **DECISION**: If roadmap is complete, EXIT. If more definition needed, LOOP back to DEFINE.
- **EARLY EXIT**: When deliverables are ready, stop and present results.
